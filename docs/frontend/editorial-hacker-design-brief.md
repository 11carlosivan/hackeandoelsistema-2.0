# Brief Visual: Identidad Hacker Editorial

Hackeando el Sistema debe sentirse hacker, critico y directo, pero tambien confiable como medio digital. La identidad visual no debe esconder la noticia: debe darle caracter, ritmo y recordacion.

## Posicionamiento Visual

La marca vive en la interseccion de:

- medio politico y de opinion.
- investigacion ciudadana.
- cultura hacker.
- actualidad dominicana.
- denuncia y analisis.

El diseño debe transmitir:

- energia.
- urgencia.
- criterio editorial.
- independencia.
- lectura clara.
- autoridad.

Debe evitar transmitir:

- sitio ficticio.
- dashboard de videojuego.
- blog generico.
- plantilla oscura sin jerarquia.
- terminal decorativa en exceso.

## Paleta

La paleta principal se conserva:

- Negro/base oscuro.
- Rojo de sistema/marca.
- Blanco para jerarquia y lectura.
- Grises para separadores, fondos y estados secundarios.

Uso recomendado:

- Negro como base dominante.
- Rojo para acentos, categoria activa, breaking news, botones principales y estados criticos.
- Blanco para titulares y lectura principal.
- Gris claro para metadata, excerpts y bordes.
- Verde u otros colores solo para estados puntuales, no como identidad principal.

Evitar:

- saturar todos los bordes en rojo.
- usar rojo para cada texto pequeño.
- convertir cada bloque en alerta.
- usar glow constante.

## Tipografia

La marca puede usar una tipografia fuerte para titulares, pero los cuerpos largos necesitan legibilidad editorial.

Recomendacion:

- Titulares: condensada, fuerte, con presencia.
- Bajadas/excerpts: sans legible.
- Cuerpo de articulo: sans de lectura o serif editorial si se decide elevar el tono.
- Metadata: mono o sans compacta, pero en dosis pequeñas.

Reglas:

- No usar todo en mayusculas en cuerpos largos.
- No usar tracking excesivo en textos de lectura.
- No forzar titulos largos en una sola linea.
- No hacer que una fuente decorativa cargue todo el sitio.

## Lenguaje UI

El lenguaje hacker debe aparecer como capa de marca, no como ruido constante.

Usar con moderacion:

- "Sistema".
- "Fuente".
- "Archivo".
- "Reporte".
- "Ultima hora".
- "Investigacion".
- "Opinion".
- "Network".

Evitar como lenguaje fijo en todo el sitio:

- "Agente".
- "Clearance".
- "Terminal".
- "Encriptado".
- "Nodo".
- "Protocolo".
- "Intel global".
- "Acceso nivel 5".

Excepcion:

- Pueden usarse en secciones especificas donde tenga sentido de marca, por ejemplo contacto seguro, denuncias, o una campaña editorial especial.

## Home

La home debe sentirse como portada de medio, no como dashboard.

Debe priorizar:

- noticia principal clara.
- ultimas noticias visibles.
- secciones por categoria.
- opinion reconocible.
- tendencias.
- anuncios sin romper lectura.
- newsletter.

Estructura recomendada desktop:

- header fijo o semi-fijo sobrio.
- fila de breaking news.
- grid principal con hero + secundarias + tendencias.
- bloque de ultimas noticias.
- opinion.
- categorias.
- footer editorial.

Estructura recomendada mobile:

- logo visible.
- menu compacto.
- breaking news corto.
- hero vertical.
- cards una debajo de otra.
- no sobrecargar sidebar.

## Articulo

La pagina de articulo es la pantalla mas importante para SEO y confianza.

Debe mostrar:

- categoria.
- titulo.
- bajada.
- autor.
- fecha publicada.
- fecha modificada si aplica.
- imagen con alt/caption/credit.
- cuerpo legible.
- compartir.
- relacionados.
- anuncios.

Prioridades:

- lectura limpia.
- ancho de columna controlado.
- buen espaciado entre parrafos.
- titulares que respiren.
- metadata visible pero no protagonista.

Evitar:

- hero tan alto que retrase el contenido.
- overlays oscuros que dificulten leer.
- scanlines sobre imagen principal en articulos.
- sidebars que compitan con la lectura.
- claims de veracidad si no hay proceso real.

## Categorias

Las categorias deben ayudar a explorar, no verse como filtros tecnicos.

Debe mostrar:

- nombre de categoria.
- descripcion si existe.
- subcategorias si aplica.
- listado paginado.
- posts destacados de la categoria.
- anuncios.

Ejemplos de categorias reales:

- Nacionales.
- Politica.
- Internacionales.
- Opinion.
- Economia & Negocios.
- Salud.
- Educacion.
- Santo Domingo.

## Autor

La pagina de autor debe reforzar confianza editorial.

Debe mostrar:

- nombre.
- avatar.
- bio.
- redes si existen.
- cantidad o listado de publicaciones.
- articulos recientes.

Evitar:

- convertir al autor en personaje ficticio.
- "clearance" o rangos si no son parte real de la marca.

## Busqueda

Busqueda debe ser funcional y rapida.

Debe mostrar:

- query.
- total.
- resultados.
- filtros si se agregan.
- estado sin resultados.

SEO:

- `NOINDEX, FOLLOW`.

## Ads

Los anuncios deben sentirse integrados al medio.

Reglas:

- reservar espacio para evitar CLS.
- etiquetar como publicidad cuando corresponda.
- no usar placeholders ficticios en produccion.
- no empujar el contenido principal hacia abajo de forma agresiva.

## Componentes Base

Antes de diseñar pantallas finales, crear:

- `SiteHeader`.
- `SiteFooter`.
- `BreakingNewsBar`.
- `PostCard`.
- `FeaturedPostCard`.
- `PostMeta`.
- `CategoryBadge`.
- `AuthorByline`.
- `AdSlot`.
- `NewsletterBlock`.
- `Pagination`.
- `EmptyState`.
- `SeoJsonLd`.

## Criterios de Calidad Visual

Una pantalla esta bien encaminada si:

- se reconoce la marca en 3 segundos.
- se entiende la noticia principal en 3 segundos.
- se puede leer un articulo largo sin fatiga.
- el mobile no se siente apretado.
- los anuncios no rompen la experiencia.
- los titulos largos no destruyen la grilla.
- el rojo guia la atencion, no grita en todas partes.
- lo hacker suma identidad, no reemplaza al periodismo.

## Referencia de Tono

Mas cercano a:

- medio independiente con identidad fuerte.
- investigacion editorial.
- portada oscura premium.
- politica/opinion con filo.

Menos cercano a:

- consola de videojuego.
- simulador de hacking.
- template cyberpunk generico.
- panel admin disfrazado de sitio publico.

## Decision Principal

Conservar:

- negro/rojo/blanco.
- energia hacker.
- marca fuerte.
- acentos tecnicos.

Reducir:

- textos de terminal.
- badges decorativos sin data real.
- ruido visual.
- animaciones constantes.
- lenguaje ficticio en noticias.

Elevar:

- jerarquia editorial.
- lectura.
- SEO visible.
- confianza.
- consistencia.
